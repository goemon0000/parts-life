# パーツ一行（Parts Party）— 企画書

PCパーツのキャラクターが、実機の稼働状況をそのまま姿で表し、
その働きぶりが勝手に物語になっていく常駐アプリ。

作成日: 2026-09-07 / 状態: プロット（実装前）

---

## 0. 一行で言うと

**「タスクマネージャーの、数字が読めないかわりに、部品が生きている版」**

見えるのは数字ではなく、部品たちの様子。
そして彼らがその日どれだけ働いたかが、そのまま冒険の進み具合になる。

---

## 1. これは何で、何ではないか

### やること
- 実機のCPU・メモリ・GPU・ディスクの稼働を、キャラの姿と動きで表す
- 下矢印を押すと、各パーツの詳しい数値（コア別など）が開く
- 上部で、干渉できない冒険が勝手に進む
- 透明背景・最前面・位置固定。場所を取らない

### やらないこと
- **プロセス一覧は出さない。** タスクマネージャーの代わりではない。
  プロセス名を見せると「監視ツール」になり、他人に画面を見せづらくなる
- **プレイヤーの操作を受け付けない。** 育成も選択肢も無い。
  干渉できないからこそ、点けっぱなしにできる
- **CPU温度・ファン回転数は v1 では出さない**（後述）

## 2. 見た目

### 全体（畳んだ状態）

```
┌──────────────────────────────────────────┐
│  第二章 灼熱の谷                            │  ← 章題（小さく）
│  GPUくんが先頭に立った。まだ息はある。          │  ← 物語（2〜3行）
│  後ろで CPUくんが数を数えている。               │
├──────────────────────────────────────────┤
│    ╔═══════════════ 基板 ═══════════════╗   │
│    ║ [ソケット]    [DIMM][DIMM]   [M.2] ║   │  ← パーツが挿さる場所
│    ║    🌀▣          ▤   ▤        ▭    ║   │
│    ║  ┌────── PCIe ──────┐            ║   │
│    ║        ▬▬▬▬▬                     ║   │
│    ╚══════════════════════════════════╝   │
├──────────────────────────────────────────┤
│                    ▼                     │
└──────────────────────────────────────────┘
```

**基板の配置は実物どおりにする。** CPUはソケット、メモリはDIMMスロット、
GPUはPCIe、SSDはM.2。飾りではなく、見ているだけで「何がどこに挿さるか」が
伝わるようにする。これはPCパーツのサイトが配るものとして意味がある。

### 展開した状態（下矢印）

```
├──────────────────────────────────────────┤
│  CPU  ▪▪▫▪ ▪▫▫▪ ▪▪▪▫ ▫▫▪▫   62%  4.1GHz   │  ← 粒1つ＝1論理コア
│  MEM  ████████████░░░░░░░   24.1 / 32 GB  │
│  GPU  ██████████████████░   91%  7.2/8 GB │
│  SSD  ▲12MB/s ▼104MB/s      412 / 931 GB  │
└──────────────────────────────────────────┘
```

数値を出すのはここだけ。畳んでいる間は数字を見せない。

### 稼働状況をどう姿で表すか（文字を使わない）

| 状況 | 見え方 |
|---|---|
| 使用率が上がる | ファンの回転が速くなる／体の上下が速くなる |
| 高負荷が続く | 表情が「必死」に変わる。体に熱の色が乗る |
| メモリ逼迫 | メモリくんが荷を抱えて傾く |
| ディスク書き込み | HDDくんの円盤が回り、書き込みの印が出る |
| ほぼ無負荷 | 寝る（既存の `sleep` モーション） |
| デバイスを挿した | その場に新しいキャラが増える |

既存のモーション（待機・歩く・腰かける・ロープ・覗き込む・喜ぶ・寝る・
ぶら下がる・驚く）と表情5種、マーク（zzz / ‼ / ♪ / ○△✕）を流用する。
**歩き回らせない。** 位置は固定で、その場での動きだけにする。

## 3. 複数構成とサーバー用途

**原則: 物理デバイス1つにつきキャラ1体。** これを崩さなければ構成が何であれ破綻しない。

| 構成 | 表示 |
|---|---|
| CPU 2ソケット | CPUくんが2体。コアはソケット単位で束ねる |
| 128論理コア | 粒を16×8のグリッドに。1粒=1論理コア、色=負荷 |
| GPU 複数 | 台数ぶん並ぶ。内蔵GPUも1体として数える |
| GPUなし（サーバー） | PCIeスロットが空いた基板になる。欠けても崩れない |
| ドライブ多数 | 代表1体＋展開時に全台のリスト |
| メモリ 8枚差し | DIMMスロットを8つ描く。埋まっている所だけキャラが立つ |

窓の幅は構成に応じて伸びる。極端な構成（4ソケット等）では基板を2段にする。

## 4. 取れる情報と、取らない情報

Windowsでは、管理者権限が要るものと要らないものがはっきり分かれる。
**v1は権限が要らないものだけで作る。**

| 情報 | 権限 | 取り方 |
|---|---|---|
| CPU 論理コア別使用率 | 不要 | `NtQuerySystemInformation(SystemProcessorPerformanceInformation)` |
| CPU クロック | 不要 | `\Processor Information(*)\% Processor Performance` |
| 物理CPU・コア構成 | 不要 | `GetLogicalProcessorInformationEx` |
| メモリ 使用量 | 不要 | `GlobalMemoryStatusEx` |
| GPU 使用率 | 不要 | PDH `\GPU Engine(*)\Utilization Percentage` をアダプタ単位で合算 |
| GPU VRAM | 不要 | PDH `\GPU Adapter Memory(*)\Dedicated Usage` |
| GPU 温度 | 不要 | NVML（NVIDIA）/ ADLX（AMD）。**あれば出す、無ければ黙る** |
| ディスク 読み書き・使用率 | 不要 | PDH `\PhysicalDisk(*)\...` |
| ドライブ空き容量 | 不要 | `GetDiskFreeSpaceEx` |
| 静的な型番・容量 | 不要 | WMI（起動時に1回だけ、別スレッドで） |
| **CPU温度・ファン・電圧** | **要（カーネルドライバ）** | **v1では実装しない** |

### CPU温度を諦める理由

カーネルドライバを積むと ①管理者権限が必須 ②ウイルス対策ソフトの誤検知
③配布物としての信用問題、が同時に乗る。ゆるいお遊びツールが払うコストではない。

**代わりに「使用率＝仕事量」を熱の代わりに使う。** 90%が続けば
「クーラーくんが必死に回っている」で十分伝わる。
将来、設定で明示的に有効にした人だけドライバを入れる、という形なら足せる。

## 5. お遊び要素：勝手に進む物語

### 設計の芯

放置ゲーで干渉できないものを普通に作ると、**ただのログが流れているだけ**で飽きる。
面白くする方法は一つしかないと考えている。

> **物語を乱数で進めない。その人のマシンの「その日の使われ方」を物語にする。**

| 実機で起きたこと | 物語 |
|---|---|
| GPU 90%が2時間続いた | 「一行は灼熱の谷を越えた。GPUくんが先頭に立ち、他は彼の背中を見ていた」 |
| 全コアが張り付いた（ビルド等） | 「CPUくんが全ての腕を開いた。門は軋みながら開いた」 |
| 夜間ずっとアイドル | 「焚き火。HDDくんが昔の話を始めた。誰も遮らなかった」 |
| メモリ使用率95% | 「メモリくんが荷を落とした。何を持っていたか、本人も思い出せない」 |
| ディスク残量が減った | 「SSDくんの背袋が膨れている。そろそろ捨てる物を選ぶ頃だ」 |
| 再起動した | 「夜が明けた」 |
| USBメモリを挿した | 「旅の途中、見慣れぬ者が一行に加わった」 |
| 数日ぶりに起動した | 「長く留守にしていた。埃が積もっている」 |

### 二重構造

- **本筋（アーク）**: 順番の決まった章。`旅程` が貯まると次へ進む。書き下ろし
- **傍白（イベント）**: 条件で出る短い場面。本筋とは独立。何度も出てよい

本筋があるから「進んでいる」と分かり、傍白があるから「自分の使い方を見られている」と感じる。
どちらか片方だけでは成立しない。

### 能力値は実機から出す

| 実機 | 能力 | 物語での効き方 |
|---|---|---|
| 論理コア数 | 手数 | 多いほど、場面を一人で片付ける |
| メモリ容量 | 積載量 | 多いほど、忘れ物をしない |
| VRAM | 魔力 | 多いほど、大きな術が通る |
| ストレージ容量 | 記憶 | 多いほど、過去の場面を覚えている |
| ストレージ空き | 余裕 | 少ないと、拾い物を捨てる場面が増える |

**自分のPCがそのままパーティになる。** 他人と絶対に同じにならない。
PCパーツのサイトが配るものとして、これ以上ない筋だと思う。

### 進行速度

`旅程` は仕事量から貯まる。ただし**対数で頭打ちにする**。
128コアのサーバーが1日で完結してしまうのを防ぐため。

```
1日の旅程 ≈ K × log(1 + CPUコア秒 + GPU秒×a + 書き込みGB×b)
```

つまり **性能は「場面の解決のされ方」を変え、使用量は「進む速さ」を変える。**
強いマシンでも物語は数週間かかるが、同じ場面での描写が違う。

### 各キャラのレベル

キャラは**自分の仕事でだけ**育つ。CPUくんはCPUの仕事で、SSDくんは書き込みで。
だからゲーマーのGPUくんは高レベルになり、動画編集者のSSDくんが高レベルになる。
**パーティ構成がその人の使い方の鏡になる。**

### 文体

**三人称の地の文だけ。セリフを書かない。**
サイトのマスコットが喋らない決めと揃うし、こちらの方が良い文章になる。
短く、少し硬い日本語。観測記録のような手触り。

### 世界の言葉

| 語 | 意味 |
|---|---|
| 盤（ばん） | この世界。マザーボードのこと |
| 外（そと） | ネットワークの向こう |
| 客人（まろうど） | 外から来たデータ |
| 送り出す | 削除する |
| 灯（あかり） | 電源が入っていること |
| 長い夜 | シャットダウン／スリープ |

### 本筋の骨組み（第一部・全10章の案）

| 章 | 題 | 引き金 | 内容 |
|---|---|---|---|
| 序 | 灯る | 初回起動 | 一行が目を覚ます。誰がどこに挿さっているかが分かる |
| 一 | 盤の上 | 旅程 少 | 世界の端まで歩く。外の存在を知る |
| 二 | 灼熱の谷 | GPU高負荷の累計 | 熱が出る場所。GPUくんが先頭に立つ |
| 三 | 積みすぎた荷 | メモリ逼迫の累計 | 持ちきれない。何を捨てるかの話 |
| 四 | 長い夜 | シャットダウン回数 | 一行が眠る。目覚めるたび少しずつ記憶が欠ける |
| 五 | 門 | 全コア高負荷 | 力ずくで開ける場面。手数が物を言う |
| 六 | 客人 | 外部デバイス接続 | 加わる者と、去る者 |
| 七 | 古い地図 | HDD/古い部品の存在 | 一番の古参が知っていること |
| 八 | 溢れる | 空き容量の逼迫 | 捨てる決断 |
| 九 | 静かな日 | 長時間アイドル | 何も起きない章。ここが効くと全体が締まる |
| 十 | 盤の外へ | 旅程 大 | 第一部の締め |

**「九 静かな日」を必ず入れる。** 何も起きない章があるから、他の章が立つ。

### データの形

物語はコードに埋めない。差し替えと追記ができる形で持つ。

```jsonc
// story/arc.json（本筋）
{
  "chapter": 2,
  "title": { "ja": "灼熱の谷", "en": "The Scorching Valley" },
  "require": { "journey": 1200, "gpuHours": 2 },
  "scenes": [
    {
      "text": { "ja": "谷は熱を持っていた。GPUくんが先に立った。" },
      "variants": [
        { "when": { "party.gpu.level": { ">=": 5 } },
          "ja": "GPUくんは一人で押し戻した。" },
        { "when": { "party.gpu.level": { "<": 5 } },
          "ja": "三人がかりで、ようやく支えた。" }
      ]
    }
  ]
}
```

**場面を足すのに再ビルドが要らない**形にする（JSONを読むだけ）。
面白さは章と場面の数に比例するので、後から書き足せることが一番重要。

## 6. 技術構成

| 層 | 使うもの | 理由 |
|---|---|---|
| 土台 | **.NET 8 / WPF** | 透過窓・最前面が素直。単一exeで配布できる。常駐50〜70MB |
| 描画 | `WriteableBitmap` + `NearestNeighbor` | ドット絵を等倍で置くだけ |
| 絵 | **TypeScriptから書き出したスプライトアトラス** | 後述 |
| センサー | P/Invoke（NtQuery・PDH・WMI） | 権限不要の範囲で完結 |
| 保存 | `%APPDATA%/PartsParty/state.json` | 物語の進行と設定 |
| 配布 | GitHub Releases → サイトからリンク | |

### 絵をどう共有するか（重要）

**TypeScript側を正とし、アトラスを書き出してC#に渡す。**

```
indie-pc-portal/src/lib/mascot/*.ts      ← 絵の正（サイトと共通）
        │  npx tsx scripts/export-atlas.ts
        ▼
parts-party/assets/atlas.png + atlas.json  ← 470枚ぶんの切り出し表
        │
        ▼
C#アプリは切り出して置くだけ
```

こうすれば **C#側にドット絵のコードを一切持たない。**
サイトでキャラを直したら、書き出し直すだけでアプリにも反映される。
二重管理にならないことが、この構成の一番の価値。

### 常駐時の負荷目標

| 項目 | 目標 |
|---|---|
| CPU | 平常時 0.5% 未満（1コア換算） |
| メモリ | 80MB 未満 |
| 更新間隔 | センサー 1秒 / 描画は変化があったときだけ |
| 展開時 | センサー 0.5秒 |

**監視ツールが重かったら本末転倒。** ここは実測して守る。

## 7. 配布とライセンス

- **コード: MIT** — 自由に流用可
- **キャラクターの絵: CC BY 4.0** — **作者名の表示が法的に必須**

コードだけMITだと、必須なのは「ライセンス文の同梱」であって画面上のクレジットではない。
守りたいのはキャラなので、絵にCC BYを掛けることで実効性を持たせる。
「UIに必ず表示せよ」を強制する独自ライセンスは、企業やOSS界隈から敬遠されるので採らない。

### 配布時に必ず起きること

**署名していないexeは、初回に「WindowsによってPCが保護されました」が出る。**
これは避けられない。対応は次のいずれか。

1. ダウンロードページに**警告が出ることと「詳細情報 → 実行」の手順を先に書く**（最低限）
2. コード署名証明書を取る（年3〜5万円）
3. OSS向けの無料署名（SignPath 等）に申請する

配布を始める前に、少なくとも 1 は必ずやる。

## 8. 工程

| 段階 | 中身 | 完了の目安 |
|---|---|---|
| **第1段** | アトラス書き出し／透過・最前面・位置固定の窓／基板とキャラの並び／CPU・メモリ・GPU・ディスクの実データでキャラの状態が変わる／下矢印で展開 | 常駐して1日使って、負荷目標を満たし、邪魔にならない |
| **第2段** | 物語層（実機由来の能力値、旅程、本筋10章、傍白イベント、上部のログ表示） | 1週間使って「今日はここまで進んだ」が読める |
| **第3段** | 複数CPU/GPU・サーバー構成・多数ドライブ・設定画面・自動起動・英語対応 | 2ソケット機とGPU無し機で崩れない |
| **第4段** | 配布（GitHub Releases・署名・サイトのダウンロードページ） | 警告の手順込みで案内できる |

**第1段が終わるまで物語には手を付けない。** 常駐して困らないことを先に確かめないと、
物語を作り込んでから土台をやり直すことになる。
