# パーツぐらし / Parts Life

PCパーツのキャラクターが、実機の稼働状況をそのまま姿で表す常駐アプリ。
そして彼らがその日どれだけ働いたかが、勝手に冒険の物語になっていく。

**タスクマネージャーの、数字が読めないかわりに、部品が生きている版。**

> ⚠ **お断り**
> このアプリのキャラクターが見せる規格・相性・物語は、すべて**お遊び**です。
> 購入や設定の判断には使えません。実際の対応可否は製品の仕様をご確認ください。

---

## できること

- CPU・メモリ・GPU・ディスクの稼働を、**数字ではなくキャラクターの姿と動き**で表す
- **働くほど熱を帯びる。** 輪郭が赤熱し、頭から湯気が昇る
- **実機の構成どおりに並ぶ。** GPU が2枚なら GPU くんも2体、CPU が2個なら2体
- 下矢印を押すと、各パーツの数値（論理コアごとの負荷、VRAM、容量）が開く
- 上部で、干渉できない冒険が勝手に進む
- 透明背景・最前面・右上に固定。場所を取らない

## やらないこと

- **プロセス一覧は出さない。** タスクマネージャーの代わりではない
- **操作を受け付けない。** 育成も選択肢も無い。干渉できないから点けっぱなしにできる
- **管理者権限を要求しない。** そのため CPU温度・ファン回転数は表示しない（下記）

### CPU温度を出さない理由

Windows で CPU温度・ファン回転数・電圧を読むには**カーネルドライバ**が要ります。
それを積むと ①管理者権限が必須 ②ウイルス対策ソフトの誤検知 ③配布物としての信用問題
が同時に乗ってきます。お遊びの常駐アプリが払うコストではないと判断しました。

代わりに **「使用率＝仕事量」を熱の代わりに**使っています。
90%が続けばクーラーくんが必死に回り、赤熱して湯気を上げるので、それで十分伝わります。

（GPU温度はベンダーのライブラリ経由で権限なしに読めるため、将来対応する可能性があります）

## 動作環境

- Windows 10 (1809以降) / Windows 11、64bit
- 追加のインストールは不要（自己完結。.NET も要りません）
- **`PartsLife.zip`（56MB）を推奨。** 展開して `PartsLife.exe` を実行してください
- `PartsLife.exe`（62MB）は展開せずそのまま動きますが、**常駐中の占有が倍近くになります**
  （実機で 222MB / 130MB）。単一ファイルの自己圧縮は、起動時に中身を
  まるごとメモリへ展開するためです。資源の使用量を眺めるためのアプリが
  その倍を自分で使っていては話にならないので、ZIP の方を勧めています

（設定と物語の進行だけ `%APPDATA%\PartsLife\` に保存します）。

## ビルド

```powershell
# 開発用
dotnet build src/PartsLife/PartsLife.csproj

# 配布用（単一 exe・自己完結）
dotnet publish src/PartsLife/PartsLife.csproj -c Release -o dist
```

必要なもの: .NET 10 SDK。
Linux からでも `-p:EnableWindowsTargeting=true`（csproj に設定済み）でビルドできます。

### キャラクターの絵を作り直す

絵の正は **TypeScript 側（`sprites/`）** にあります。
C# 側にドット絵を描くコードは持っていません（二重管理でズレるため）。

```bash
npm install
npm run export:atlas     # sprites/ から assets/ を焼き直す
```

### 見た目を確認する

画面のある機械でしか確認できないと、直すたびに往復が要ります。
**窓を開かずに、絵と実測値だけを書き出せます。**

```powershell
PartsLife.exe --shot   out.png 2            # いまの見た目そのまま1枚に（宣材もこれで作っている）
PartsLife.exe --shot   out.png 2 --collapsed
PartsLife.exe --render out.png 1.0 3        # 負荷 1.0 の基板を6コマぶん。湯気の動きが見える
PartsLife.exe --render server.png 0.9 3     # ファイル名に server を含めると2CPU/4GPU構成
PartsLife.exe --probe  out.txt              # GPU・ディスクを実機がどう見ているか
```

## 物語を書き足す

本文は [`assets/story.json`](assets/story.json) にあり、**C# を触らずに足せます**。

- `chapters[].scenes[]` … 旅程が `scenePer` 進むごとに1つずつ出る
- `events[]` … `when` の条件を満たしたときに出る傍白。`cooldown` 秒は再登場しない

`when` に使える条件（この名前だけが解釈されます）:
`cpu-very-high` / `gpu-very-high` / `memory-tight` / `disk-busy` / `disk-full` /
`idle-long` / `boot` / `long-absence` / `level-up`

文体の決まりは1つだけ。**三人称の地の文で書き、セリフを書かないこと。**
喋らせた瞬間に、常駐していて邪魔にならないものではなくなります。

## 進み方の目安

| | 1場面進むまで | CPUくんが Lv10 まで |
|---|---|---|
| 放置（待機） | 約1分 | 約1時間半 |
| CPU全負荷 | 約16秒 | 約8分 |

経験値は**その子自身の仕事でしか増えません**。
GPU が2枚あれば、回っている方だけが育ちます。
