# パーツぐらし / Parts Life

PCパーツのキャラクターが、実機の稼働状況をそのまま姿で表す常駐アプリ。
そして彼らがその日どれだけ働いたかが、勝手に冒険の物語になっていく。

**タスクマネージャーの、数字が読めないかわりに、部品が生きている版。**

> ⚠ **お断り**
> このアプリのキャラクターが見せる規格・相性・物語は、すべて**お遊び**です。
> 購入や設定の判断には使えません。実際の対応可否は製品の仕様をご確認ください。

---

## できること

- CPU・メモリ・GPU・ディスクの稼働を、**数字ではなくキャラクターの姿と動き**で表す
- **働くほど熱を帯びる。** 輪郭が赤熱し、頭から湯気が昇る
- **実機の構成どおりに並ぶ。** GPU が2枚なら GPU くんも2体、CPU が2個なら2体
- 下矢印を押すと、各パーツの数値（論理コアごとの負荷、VRAM、容量）が開く
- 上部で、干渉できない冒険が勝手に進む。町で休み、装備を整え、行き先を自分で決めて出かける
- 右クリック →「点検…」で、**システムチェック・負荷テスト（CPU・メモリ）・記憶媒体の精密チェック**の窓が開く
  （常駐の窓とは別。押したときだけ動く。下記「点検」）
- 透明背景・最前面・右上に固定。場所を取らない

## やらないこと

- **プロセス一覧は出さない。** タスクマネージャーの代わりではない
- **操作を受け付けない。** 育成も選択肢も無い。干渉できないから点けっぱなしにできる
- **管理者権限を要求しない。** そのため CPU温度・ファン回転数は表示しない（下記）
  （例外は「記憶媒体の精密チェック」だけ。押したときに、別の小さな exe が UAC で許可を求める）

### CPU温度を出さない理由

Windows で CPU温度・ファン回転数・電圧を読むには**カーネルドライバ**が要ります。
それを積むと ①管理者権限が必須 ②ウイルス対策ソフトの誤検知 ③配布物としての信用問題
が同時に乗ってきます。お遊びの常駐アプリが払うコストではないと判断しました。

代わりに **「使用率＝仕事量」を熱の代わりに**使っています。
90%が続けばクーラーくんが必死に回り、赤熱して湯気を上げるので、それで十分伝わります。

（GPU温度はベンダーのライブラリ経由で権限なしに読めるため、将来対応する可能性があります）

## 動作環境

- Windows 10 (1809以降) / Windows 11、64bit
- 追加のインストールは不要（自己完結。.NET も要りません）
- **`PartsLife.zip`（56MB）を推奨。** 展開して `PartsLife.exe` を実行してください
- `PartsLife.exe`（62MB）は展開せずそのまま動きますが、**常駐中の占有が倍近くになります**
  （実機で 222MB / 130MB）。単一ファイルの自己圧縮は、起動時に中身を
  まるごとメモリへ展開するためです。資源の使用量を眺めるためのアプリが
  その倍を自分で使っていては話にならないので、ZIP の方を勧めています
- 点検の「記憶媒体の精密チェック」には、ZIP に同梱の `PartsLife.Check.exe`（2MB）が
  `PartsLife.exe` と同じフォルダに要ります。単体の exe だけでは、そこだけ使えません

## ビルド

```powershell
# 開発用
dotnet build src/PartsLife/PartsLife.csproj

# 配布用（単一 exe・自己完結）
dotnet publish src/PartsLife/PartsLife.csproj -c Release -o dist

# 点検の管理者の補助 exe（NativeAOT。dist に本体と並べて置く）
dotnet publish src/PartsLife.Check/PartsLife.Check.csproj -c Release -o dist

# 点検の中身のテスト（この版で出す機能と止めてある機能の切り替えも見る）
dotnet test tests/PartsLife.Checks.Tests
```

必要なもの: .NET 10 SDK。補助 exe の NativeAOT には Visual Studio の C++ ビルドツールも要ります
（`vswhere.exe` が PATH に無いと「'vswhere.exe' は…認識されていません」で止まる。
`C:\Program Files (x86)\Microsoft Visual Studio\Installer` を PATH に足す）。
Linux からでも `-p:EnableWindowsTargeting=true`（csproj に設定済み）でビルドできます。

### キャラクターの絵を作り直す

絵の正は **TypeScript 側（`sprites/`）** にあります。
C# 側にドット絵を描くコードは持っていません（二重管理でズレるため）。

```bash
npm install
npm run export:atlas     # sprites/ から assets/ を焼き直す
```

### 見た目を確認する

画面のある機械でしか確認できないと、直すたびに往復が要ります。
**窓を開かずに、絵と実測値だけを書き出せます。**

```powershell
PartsLife.exe --shot   out.png 2            # いまの見た目そのまま1枚に（宣材もこれで作っている）
PartsLife.exe --shot   out.png 2 --collapsed
PartsLife.exe --render out.png 1.0 3        # 負荷 1.0 の基板を6コマぶん。湯気の動きが見える
PartsLife.exe --render server.png 0.9 3     # ファイル名に server を含めると2CPU/4GPU構成
PartsLife.exe --probe  out.txt              # GPU・ディスクを実機がどう見ているか（盤に立てない物は理由つき）
PartsLife.exe --story  out.txt              # 物語を全場面書き出す（構成違いの2通り）
PartsLife.exe --shot-check out.png system 1 # 点検の窓の一面（system / load / storage）。--lang en・--width 680
```

`--shot-check` は本物の点検の窓を組み立てて描きます。`system` は管理者なしのシステムチェックを
実際に走らせた結果、`load` は何も走らせていない面、`storage` は管理者の要る読み取りの前の面です
（補助 exe は起こしません）。保存にも `checks` にも書かず、シリアル番号は末尾 4 文字だけにします。

## 点検

右クリック →「点検…」で開く別の窓。**常駐の窓は操作を受け付けないまま**です。

- **押すまで何も動きません。** 開いただけでは何も測らず、閉じれば全部止まります
- 常駐中は点検のコードを読み込みません（献立で押したときに初めて読み込む）
- **ディスクには一切書き込みません。** 表面検査も読むだけです（書くのは、構成を JSON で保存したときに自分で選んだファイルだけ）

| 面 | やること | 権限 |
|---|---|---|
| システムチェック | OS・CPU・メモリの各枚（定格と実際の速さ）・GPU とドライバ・ディスク（Windows の健康判定と空き）・ページファイル・直近 7 日のイベントログ（WHEA・disk・Ntfs・stornvme・volmgr のエラー、Kernel-Power 41） | 不要 |
| 負荷テスト | CPU（全論理コア・コア別・持続性・実効クロック・計算の答え合わせ）/ メモリ（空きの 10〜50% に模様を書いて照合）。30 秒・2 分・5 分 | 不要 |
| 記憶媒体の精密チェック | NVMe の Health ログ・SATA の SMART を読み、**前回からの増え方**を出す（「メディアエラー 1,204 → 1,227 (+23)」）。任意で読むだけの表面検査 | **要（UAC）** |

結果は OK / 注意 / 要確認 / 測れず の4つ。**測れなかった物を OK とは言いません。**
CPU の温度は相変わらず測りません（カーネルドライバが要るため）。

### 記憶媒体の精密チェック

v0.7.0 では止めて出し、実機（NVMe と SATA の SSD・HDD）で人が付き添って確かめたうえで、
**v0.7.1 から有効にしました。**

記憶媒体の精密チェックだけは、Windows の決まりで管理者が要ります。そこで本体ではなく、
**別の小さな exe（`PartsLife.Check.exe`、ZIP に同梱）に閉じ込めて**あります。本体は管理者を要求しないままです。
押したときだけ UAC で許可を求め、読んだ結果をパイプで返して終わります。ネットワークにもファイルにも書きません。
UAC で「いいえ」を選べば、何もせずに終わります。

- 読んだ数字は本体が `%APPDATA%\PartsLife\checks\` に残し、**次の点検で前回からの増え方**を出します
- 表面検査は任意で、**読むだけ**です（標本を飛び飛びに読む形と、全部読む形）。途中で止められます
- USB の外付けなど、間に変換基板があって読めない物は、推測せず「この接続では読めません」と出します
- 単体の `PartsLife.exe` には補助 exe が付かないので、そちらではこの面だけ使えません

補助 exe は物理ディスクを開くとき、まず読み取り権だけで開きます。読み書き権の handle を使うのは
Windows がそれを求める問い合わせだけです（SATA の SMART は常に、NVMe のログは読み取り権では
「権限が足りない」と返す機種に限る）。どちらの handle でも投げるのは読み出しの命令だけです。

補助 exe は Downloads に展開されたまま管理者で動くので、**隣に置かれた DLL を読み込まない**ようにしてあります
（静的な取り込みは `/DEPENDENTLOADFLAG:0x800`、実行時は `SetDefaultDllDirectories` と System32 への差し替え）。
発行のたびに、exe の隣も探す読み込みが紛れ込んでいないかを検査し、あれば発行を止めます。
取り込みの一覧は `dumpbin /imports PartsLife.Check.exe` で確かめられます
（KnownDLLs 以外は bcrypt.dll だけ。System32 から読む）。

### 構成コード（web-autoai.com のマイPCに登録）

システムチェックの面の下にある「**構成コードをコピー**」で、この PC の部品の型番を 1 行の文字列にして
クリップボードへ写します。web-autoai.com の「マイPC登録」（`/my-config`）に貼り付けると、PC 全体を
マイPCとして登録でき、そのまま BTO のページで「どこを変えると良くなるか」を見られます。

- **このアプリは送信しません。** 写す（または「構成をJSONで保存」で `parts-life-build.json` に保存する）だけで、
  貼るかどうかは使う人が決めます。「中身を見る」で、渡す物をそのまま確かめられます
- 入るのは **型番と数字だけ**: CPU・GPU（VRAM）・マザーボード・メモリ（1 枚の容量・速さ（XMP/EXPO で定格より速く動いていればその速さ）・DDR4/DDR5 など・メーカー・枚数）・
  SSD / HDD（容量・NVMe/SATA）・モニター・光学ドライブ
- **入らない物**: シリアル番号・PC の名前・利用者名・プロダクトキー・MAC アドレス・SMART の数値・ドライブ文字やパス。
  型番の代わりにシリアル番号を返す機種に備えて、シリアルに見える文字列は落とします
- 数えない物: CPU 内蔵の GPU・仮想ディスプレイ（VR のストリーミング・リモートデスクトップ）・標準のディスプレイドライバ・
  USB の記憶装置（USB メモリ・外付け）・仮想ディスク・ISO の仮想ドライブ。ネットワークとサウンドは、
  マザーボードに載っている物と増設カードを見分けられないので入れていません
- 読めなかった部品は、その分類ごと空のまま出します（推測で埋めません）

形は `PCB1.` ＋ JSON（UTF-8）の base64url です。中身の JSON は次の形（`v` は 1）:

```json
{ "v": 1, "src": "parts-life", "p": {
  "cpu": [{ "n": "AMD Ryzen 9 7950X 16-Core Processor" }],
  "gpu": [{ "n": "NVIDIA GeForce RTX 3080 Ti", "vram": 12 }],
  "ram": [{ "n": "CMK64GX5M2B5600Z40", "cap": 32, "spd": 5600, "t": "DDR5", "mfr": "Corsair", "q": 2 }],
  "ssd": [{ "n": "Corsair MP600 PRO LPX", "cap": 2000, "t": "nvme" }]
}}
```

1 分類 8 種類まで、同じ部品は `q` でまとめます。コードは 6,000 字までで、超えたときはモニター → HDD →
メモリの 2 種類目以降の順に省き、省いたことを画面に出します（普通の PC は 1,000 字前後）。
読み取りは WMI と DXGI だけで、管理者は要りません（`src/PartsLife.Checks/Build/`）。

### 次の版で（実機での確認のあと）

- **GPU の負荷テスト**（作ってあるが止めてある）: 温度を見張りながら控えめに。働かせるのは 75% の時間だけ、
  **83 ℃ で自動的に止める。** 温度を見張れない GPU（いまは NVIDIA 以外。NVIDIA はドライバ同梱の `nvml.dll` で読む）には
  負荷をかけない。実機に人が付き添って確かめるまでは配らない、と決めているため、v0.7.1 でも負荷テストの面に GPU は出ません

止め方はビルド時の定数だけ（`src/PartsLife.Checks/Features.cs`）で、環境変数や設定で後から有効にする道はありません。

## 物語

**23章231場面・傍白173本・小話240本。全793文。**

章立ての物語はいつか読み終わりますが、**小話の層は尽きません。**
1分半〜5分に1本、条件に合うものから流れます。直近に出したものは避けるので、
量があっても使い回しには見えません。

### 同じ章でも、機械が違えば違う話になる

231場面のうち **115場面**が、実機の構成と育ち具合で文を変えます。

```
GPUくんが二人とも前に出た。並んで歩いたので、道が二本できた。   ← GPUが2枚
GPUくんが先に立った。一番大きいので、後ろの者は踏む場所に困らない。 ← GPUくんが育っている
GPUくんが先に立った。一番大きいから、というのが理由の全部だった。   ← それ以外
```

### 試験

物語・レベル・冒険の決まりは `src/PartsLife.Core`（WPF を持たない層）にあり、Linux でも試験が回ります。

```bash
dotnet test tests/PartsLife.Core.Tests
```

30日ぶんを1秒刻みで回す模擬（待機・事務・遊び・描画の4通り）も含みます。

### 書き足し方

本文は [`assets/story.json`](assets/story.json) にあり、**C# を触らずに足せます**。
原稿は `story-work/` にあり、`python3 tools/build-story.py --write` で組み上がります
（冒険の原稿 `story-work/adventure-*.json` も同時に `assets/adventure.json` へ）。

```json
{ "variants": [
    { "when": "level:hdd>=10", "ja": "...", "en": "..." },
    { "ja": "どれにも当てはまらないときの文", "en": "..." } ] }
```

`when` に書ける式（**これ以外は書けません**）:

| 式 | 意味 |
|---|---|
| `level:<id><op><n>` | そのキャラのレベル。複数あるときは最も育った個体 |
| `chapter>=<n>` | 章番号 |
| `gpus>=<n>` / `cpus>=<n>` | 実機に載っている枚数・個数 |
| `has:m2` / `has:ssd` / `has:hdd` | その種類が載っているか |
| `boots>=<n>` / `hours>=<n>` | 起動回数・累計起動時間 |

演算子は `>= <= > < ==` のみ。**and / or は使えません。**
式を解釈する仕組みを広げると、本文を足したいだけの作業に
言語処理系の面倒が付いてきます。足りないと分かってから広げます。

**読めない条件は偽になります。** 真にすると綴りを間違えた条件がどこでも通り、
間違いに気づけません。`tools/build-story.py` が取り込み前に弾きます。

文体の決まりは1つだけ。**三人称の地の文で書き、セリフを書かないこと。**
喋らせた瞬間に、常駐していて邪魔にならないものではなくなります。

## 冒険（町・遠出・装備）

本筋の章と章のあいだを、一行が**自分で決めて**回る冒険が埋めます。
町で宿に泊まり、拾い物を売って装備を買い、掲示から行き先を選んで出かけ、疲れたら帰ってきます。

**利用者は何も選びません。** 場面ごとに一行が「大胆・五分・慎重」の構えを決め、
その理由が一文で流れます。理由には**実機の様子も入ります。**
高い負荷が続いていれば慎重に、機械が静かなら大胆になります。

```
盤の上が熱かった。一行は引き返した。
誰も呼ばれていない。時間はあった。一行は脇道に入った。
```

- 町8つ・行き先24・道具54・冒険の文170（日英）
- 道具の得意は部品の役どころから（CPU は手数、メモリは積載量、GPU は魔力、ディスクは粘りと拾う力）
- **レベルには一切効きません。** 経験値はこれまでどおり、その子自身の仕事でしか増えません
- 章題の横に、いま居る町か行き先が出ます。部品の上に指を置くと、着けている物が出ます

決め方の表は [`docs/plot.md`](docs/plot.md) の「冒険」にあります。

## 進み方の目安

| | 1場面進むまで | CPUくんが Lv10 まで |
|---|---|---|
| 放置（待機） | 約1分 | 約1時間半 |
| CPU全負荷 | 約16秒 | 約8分 |

最後の章に入るまで旅程 84,000。放置なら約90時間、普段使いなら1〜2ヶ月かかります。

経験値は**その子自身の仕事でしか増えません**。
GPU が2枚あれば、回っている方だけが育ちます。
